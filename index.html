Quick install

curl -fsSL https://coddy.dev/install.sh | bash
irm https://coddy.dev/install.ps1 | iex
curl -fsSLO https://github.com/coddy-project/coddy-agent/releases/latest/download/coddy_X.Y.Z_linux_amd64.deb
sudo apt-get install ./coddy_X.Y.Z_linux_amd64.deb

On Fedora, RHEL or openSUSE take the .rpm of the same name and install it with sudo dnf install ./...rpm. Swap amd64 for arm64 on 64-bit ARM, or pick a file by hand from the latest release. 

brew install --cask coddy

Until the cask lands in homebrew/cask, install it from the release asset: brew install --cask https://github.com/coddy-project/coddy-agent/releases/latest/download/coddy.rb. 

docker run -d --name coddy \
  -p 12345:12345 \
  -e OPENAI_API_KEY \
  -v "$PWD/workspace:/workspace" \
  -v "$PWD/coddy_home:/home/user/.coddy" \
  ghcr.io/coddy-project/coddy-agent:latest

Opens the web UI on localhost:12345. The image is scratch-based and multi-arch (linux/amd64, linux/arm64); the agent edits files in the mounted workspace, so mount the project you want it to work on. State - sessions, skills, config - lives in the second mount.

Pin a version instead of latest with a tag from the published images, for example ghcr.io/coddy-project/coddy-agent:1.0.19. Images are published to the GitHub Container Registry, not Docker Hub; docker pull needs no login for public images.

Or with Compose - save as docker-compose.yaml and run docker compose up -d:

services:
  coddy:
    image: ghcr.io/coddy-project/coddy-agent:latest
    command: http -H 0.0.0.0 -P 12345
    ports:
      - "12345:12345"
    working_dir: /workspace
    environment:
      CODDY_HOME: /home/user/.coddy
      CODDY_CWD: /workspace
      CODDY_CONFIG: /home/user/.coddy/config.yaml
      OPENAI_API_KEY: ${OPENAI_API_KEY-}
    volumes:
      - ./workspace:/workspace
      - ./coddy_home:/home/user/.coddy
    healthcheck:
      test: ["CMD", "/bin/coddy", "--version"]
      interval: 5s
      timeout: 3s
      retries: 20

Sources in the repository: Dockerfile, docker-compose.yml (the published image) and docker-compose.dev.yml (builds from source, so you can pick your own build tags). Full guide: docs/docker.md.

Downloads the latest release binary, installs to your PATH, and creates ~/.coddy/config.yaml from the example when missing. Then set a provider key and run coddy for the terminal console, coddy http for the web UI, or coddy acp for an editor client. Upgrade later with coddy update -y.

The packages install a binary and its documentation and nothing else: /usr/bin/coddy, man coddy, and bash and zsh completions. No service and no system account - Coddy keeps its state in your own ~/.coddy, so what to run stays your decision. Your package manager tracks the files, and coddy update defers to it instead of overwriting them: as root it downloads and installs the newer package, and a Homebrew install is sent back to brew upgrade.

What is Coddy

Coddy started as a coding agent and grew into a general-purpose harness: Cursor-style rules and skills on disk, agent, plan and ask modes, tool permissions, streaming output, and sessions you can resume from a terminal, an IDE, a browser, Telegram, or automation - the same $CODDY_HOME bundle whichever surface opens it.

Ship it as a single binary in distroless or from-scratch images, or run a fleet of containers with your orchestrator defining CPU, memory, and mounts - one agent per task, full control of each instance.

Features

Agent core

ReAct loop

Reasoning, tool calls, and observations in a loop, with runaway-loop guards on repeated output and repeated tool calls.

Three modes

agent runs the full toolset, plan writes plan documents only, ask is read-only research with web search.

Subagents

spawn_agent delegates a bounded task to a child agent with its own context and session. Markdown definitions that can only narrow the parent's tools.

Background tasks

Long commands run detached with background: true. A Tasks panel tracks them against the model's own estimate; the agent collects output later.

Compaction

/compact plus automatic summarization at a context threshold. The recent turns stay verbatim and the full transcript stays on disk.

Long-term memory

Optional memory copilot that recalls across sessions, with per-session memory routes on the HTTP surface.

Where you run it

Console

Bare coddy on a terminal. Streaming transcript, tool boxes, permission modals, coddy -c to resume, coddy -p for one-shot output.

Web UI

Embedded SPA at / with the http,ui tags. Chat, sessions, plan documents, Tasks and scheduler drawers, live settings.

ACP

coddy acp over stdio. Sessions, modes, permissions, and streaming updates for Zed, Obsidian, VS Code, or your own script.

HTTP API

OpenAI-compatible gateway on coddy http. POST /v1/responses, models, Swagger at /docs/.

Remote control

Point the console or coddy acp at a running server with --remote, or switch the web UI between local and remote from the composer.

Telegram gateway

Bot adapter with per-user sessions, group isolation modes, admin ACL, and native rich messages. Extensible to other messengers.

Project context and control

Rules

Auto-discovers .cursor/rules, .coddy/rules, .claude/rules, .codex/rules, and nested AGENTS.md under the session cwd.

Skills

Slash commands from SKILL.md packs in skills.dirs. Install from registries with npx skills or from Settings → Skills.

MCP servers

Connect MCP servers from config or per session. Their tool definitions merge into the agent and plan loops.

Permissions and trust

Edits and commands ask before they run, and a grant can widen to a whole program. Project-local MCP servers and subagent files need an explicit approval first.

Self-configuration

The agent edits its own YAML through staged config_set commands. Nothing lands until a commit you approve, which validates and hot-reloads.

Multimodal

Attach images and files in the composer when the model supports it. Assets are saved to the session directory and injected into the agent context.

Models and operations

Any provider

OpenAI, Anthropic, Ollama, NeuralDeep, any OpenAI-compatible API, plus ChatGPT sign-in through the Codex backend. Your keys, your endpoints.

Reasoning levels

A composer dropdown picks the effort for reasoning models, mapped to OpenAI reasoning_effort or Anthropic thinking budgets.

Scheduler

Cron jobs with a UI drawer and agent tools, so recurring work runs without a session open.

SSH commands

ssh_run_command reaches remote hosts over pure-Go SSH, authenticating from your SSH agent or ~/.ssh keys.

Docker and distroless

Published images on ghcr.io for amd64 and arm64, or drop the static binary into a scratch image with a read-only rootfs.

Themes and language

Seven web UI themes and an English or Russian interface, switched in Settings → Appearance without touching the config.

Questions

What is Coddy Agent?

Coddy Agent is an open-source, general-purpose AI agent that ships as one static Go binary under the MIT license. It runs a ReAct loop with filesystem and shell tools, MCP servers, project rules, skills, subagents, background tasks, a cron scheduler, and long-term memory, and the same agent is available from a terminal, a browser, an editor over ACP, or Telegram.

Which LLM providers and models does Coddy work with?

Any OpenAI-compatible API plus Anthropic: OpenAI, Anthropic, Ollama, llama.cpp, vLLM, NeuralDeep, or your own gateway, always with your own keys and endpoints. ChatGPT sign-in works through the Codex backend. Models are declared in config.yaml and switched per session.

How do I install Coddy?

Linux and macOS: curl -fsSL https://coddy.dev/install.sh | bash. Windows: irm https://coddy.dev/install.ps1 | iex. The script downloads the latest release binary, puts it on your PATH, and creates ~/.coddy/config.yaml from the example. On Linux you can instead install the .deb or .rpm published with every release, and on macOS the Homebrew cask (brew install --cask coddy); both register Coddy with your package manager and add the man page and shell completions. Docker images for amd64 and arm64 are published as ghcr.io/coddy-project/coddy-agent, and coddy update -y upgrades an existing install.

Can Coddy run on-premises with local models?

Yes. Point a model entry at a local OpenAI-compatible server such as Ollama, llama.cpp, or vLLM and no prompt leaves your network. The binary is static, so it also runs in distroless or from-scratch containers with a read-only root filesystem, one agent per task.

Which editors and clients can host Coddy?

coddy acp speaks the Agent Client Protocol over stdio, so Zed, Obsidian, VS Code, or your own script get sessions, modes, permissions, streaming updates, and skills as slash commands. coddy http serves an OpenAI-compatible REST API with the embedded web UI, and the Telegram gateway runs the same agent in chats.

How is Coddy different from other coding agents?

It is provider-agnostic and self-hosted by design: one MIT-licensed binary with no runtime dependencies, your own keys or local models, and one set of sessions shared by the terminal, web UI, editor, Telegram, and scheduler. It reads Cursor-style rules, skills, and AGENTS.md from the repository, so it fits projects already set up for other agents. See the side-by-side comparison with seventeen other harnesses.
