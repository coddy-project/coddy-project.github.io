Запустите универсального агента
из одного статического бинарника

Coddy — платформа для агентов: цикл ReAct с инструментами для файлов и командной строки, MCP, правилами проекта, навыками, субагентами, хуками, фоновыми задачами и долговременной памятью. Работайте через терминал, браузер, редактор по ACP или Telegram. Запускайте как сервис с планировщиком cron, ретранслятором для группы узлов и удалённым управлением. Подходит для контейнеров и ваших собственных ключей API.

/go-binary /console-tui /acp-harness /subagents /swarm /distroless-ready /on-prem-llms

Посмотреть скрипт установки ↗

Запустите команду в PowerShell. Она добавит бинарник последнего релиза в PATH и создаст ~/.coddy/config.yaml на основе примера, если файла ещё нет. 

docker run -d --name coddy \
  -p 12345:12345 \
  -e OPENAI_API_KEY \
  -v "$PWD/workspace:/workspace" \
  -v "$PWD/coddy_home:/home/user/.coddy" \
  ghcr.io/coddy-project/coddy-agent:latest
services:
  coddy:
    image: ghcr.io/coddy-project/coddy-agent:latest
    command: serve -H 0.0.0.0 -P 12345
    ports:
      - "12345:12345"
    working_dir: /workspace
    environment:
      CODDY_HOME: /home/user/.coddy
      CODDY_CWD: /workspace
      CODDY_CONFIG: /home/user/.coddy/config.yaml
      OPENAI_API_KEY: ${OPENAI_API_KEY-}
    volumes:
      - ./workspace:/workspace
      - ./coddy_home:/home/user/.coddy
    healthcheck:
      test: ["CMD", "/bin/coddy", "--version"]
      interval: 5s
      timeout: 3s
      retries: 20
Руководство по Docker ↗ Compose-файл в репозитории ↗

Открывает веб-интерфейс по адресу localhost:12345. Агент работает в подключённом каталоге /workspace; сессии, навыки и конфигурация находятся во втором томе. Образ собирается для amd64 и arm64 и публикуется в GitHub Container Registry — для загрузки вход не нужен. Вместо latestможно закрепить версию релиза, например ghcr.io/coddy-project/coddy-agent:X.Y.Z.

Сохраните файл как docker-compose.yaml и выполните docker compose up -d. В репозитории есть: Dockerfile, docker-compose.yml для опубликованного образа и docker-compose.dev.yml для сборки из исходников со своими тегами.

Затем укажите ключ провайдера в ~/.coddy/config.yaml и выполните

coddy
терминальную консоль
coddy serve
веб-интерфейс
coddy acp
клиент редактора по ACP
coddy update -y
обновление в будущем

Посмотрите, как это работает

Тот же агент, запущенный через coddy serve: потоковый вывод вызовов инструментов, запрос разрешения с настоящим diff, история сессий, семь тем и переключатель окружения для подключения к удалённому серверу.

Обычный запуск coddy в терминале: выберите модель через Ctrl+L, подтверждайте правки и команды во время работы агента, возобновляйте сессию через coddy -c, подключайтесь к удалённому серверу через --remote.

Zed запускает coddy acp для рабочего каталога. Режимы, модели и политика разрешений Coddy отображаются в панели агента редактора, а навыки доступны как слеш-команды. Достаточно одной записи в settings.json: 

"agent_servers": {
  "Coddy": { "type": "custom", "command": "coddy", "args": ["acp"] }
}

Что такое Coddy

Coddy начинался как агент для программирования и вырос в универсальную платформу для агентов: правила и навыки в стиле Cursor на диске, режимы agent, plan и ask , разрешения инструментов, потоковый вывод и сессии, которые можно продолжить из терминала, IDE, браузера, Telegram или автоматизации. Один и тот же каталог $CODDY_HOME используется независимо от интерфейса.

Разверните один бинарник в образе distroless или с нуля или запустите группу контейнеров под управлением оркестратора, задающего CPU, память и тома: отдельный агент для каждой задачи, полный контроль над каждым экземпляром и один ретранслятор, связывающий все узлы.

Возможности

Основа агента

Цикл ReAct

Рассуждения, вызовы инструментов и наблюдения в цикле; защита останавливает повторяющийся вывод и одинаковые вызовы инструментов.

Субагенты

spawn_agent передаёт ограниченную задачу дочернему агенту с отдельным контекстом и сессией. Определения в Markdown могут только сужать доступ к инструментам родителя.

Хуки

Ваши команды на каждом этапе жизненного цикла в формате Claude Code hooks.json . Хук может отклонить, разрешить или изменить вызов инструмента до его выполнения.

Фоновые задачи

Долгие команды запускаются в фоне через background: true. Панель задач отслеживает их относительно оценки модели; агент забирает результат позже.

Сжатие контекста

/compact и автоматическое резюмирование при заполнении контекста. Последние сообщения сохраняются без изменений, а полная история остаётся на диске.

Долговременная память

Необязательный помощник по памяти извлекает сведения из прошлых сессий; HTTP API предоставляет маршруты памяти для каждой сессии.

Где работать с агентом

Консоль

Обычный запуск coddy в терминале: потоковая история, блоки инструментов, окна разрешений, !! для локальной оболочки, недоступной модели, coddy -c для продолжения сессии, coddy -p для однократного вывода.

Веб-интерфейс

Встроенное SPA по адресу / с http,ui тегами. Чат, сессии, планы, панели задач и планировщика, карта узлов и настройки в реальном времени.

ACP

coddy acp через stdio: сессии, режимы, разрешения и потоковые обновления для Zed, Obsidian, VS Code или вашего скрипта.

HTTP API

Совместимый с OpenAI шлюз по адресу coddy serve. POST /v1/responses, модели, Swagger по адресу /docs/.

Шлюз Telegram

Адаптер бота с отдельными сессиями для пользователей, режимами изоляции групп, списком прав администратора и форматированными сообщениями. Можно расширить на другие мессенджеры.

Сессии

Наборы данных на диске в $CODDY_HOME, доступные из любого интерфейса. Отредактируйте сообщение, чтобы создать ветку диалога; экспортируйте /export в Markdown, HTML или JSON.

Управление

coddy serve

Один процесс для всех подсистем, которые config.yaml включает. --daemon оставляет его работать в фоне через status, stop и restart; изменения конфигурации применяются без перезапуска.

Рой узлов

Ретранслятор связывает несколько узлов, собирает их сессии в общий список и маршрутизирует запросы между кольцами. Узлы, способные только к исходящему соединению, подключаются через обратный туннель.

Удалённое управление

Подключите консоль или coddy acp к работающему серверу через --remoteили переключите веб-интерфейс между локальным и удалённым сервером в поле ввода.

Планировщик

Задачи cron с панелью управления и инструментами агента: повторяющаяся работа запускается без открытой сессии.

Проверка конфигурации и пробный запуск

coddy -t проверяет config.yaml по встроенной схеме с file:line:col и подсказкой для исправления. --dry-run проверяет пути, провайдеров, модели, порты, MCP-серверы и удалённые подключения до запуска.

Docker и distroless

Образы публикуются в ghcr.io для amd64 и arm64. Статический бинарник также можно поместить в минимальный образ с файловой системой только для чтения.

Контекст проекта и контроль

Правила

Автоматически находит .cursor/rules, .coddy/rules, .agents/rules, .claude/rules, .codex/rulesи вложенные AGENTS.md внутри рабочего каталога сессии.

Навыки

Слеш-команды из SKILL.md наборов в skills.dirs. Устанавливайте из каталогов через npx skills или в меню «Настройки → Навыки».

MCP-серверы

Подключайте MCP-серверы через stdio, потоковый HTTP и SSE из конфигурации, mcp.json файлов или редактора. Их инструменты доступны агенту и режиму планирования.

Три режима

agent использует все инструменты, plan создаёт только планы, ask ищет информацию в режиме только для чтения с веб-поиском.

Разрешения и доверие

Правки и команды запрашивают разрешение перед выполнением; его можно выдать для всей программы. MCP-серверы, хуки и файлы субагентов из проекта также требуют явного подтверждения.

Самонастройка

Агент редактирует собственный YAML через подготовленные команды config_set . Изменения вступают в силу только после подтверждённого вами коммита, проверки и перезагрузки конфигурации.

Модели, инструменты и внешний вид

Любой провайдер

OpenAI, Anthropic, Ollama, NeuralDeep, любой API, совместимый с OpenAI, и вход через ChatGPT с помощью Codex backend. Ваши ключи и адреса серверов.

Уровни рассуждения

В поле ввода можно выбрать усилие для рассуждающих моделей, соответствующее параметру OpenAI reasoning_effort или бюджету рассуждений Anthropic.

Мультимодальность

Прикрепляйте изображения и файлы, если модель их поддерживает. Они сохраняются в каталоге сессии и добавляются в контекст агента.

Расход и лимиты

Квота текущей модели отображается внизу консоли и в веб-интерфейсе, если провайдер её сообщает. При достижении лимита запрос может дождаться сброса и продолжиться автоматически.

Команды SSH

ssh_run_command подключается к удалённым хостам по SSH на Go, используя SSH-агент или ключи ~/.ssh .

Темы и язык

Семь тем веб-интерфейса и переключение между английским и русским языками в настройках внешнего вида без изменения конфигурации.

Вопросы

Что такое Coddy Agent?

Coddy Agent — универсальный ИИ-агент с открытым исходным кодом под лицензией MIT, поставляемый одним статическим Go-бинарником. Он выполняет цикл ReAct с инструментами для файлов и командной строки, MCP-серверами, правилами проекта, навыками, субагентами, хуками, фоновыми задачами, планировщиком cron и долговременной памятью. Один и тот же агент доступен через терминал, браузер, редактор по ACP или Telegram, на одном компьютере или в группе узлов.

С какими провайдерами и моделями работает Coddy?

Любой API, совместимый с OpenAI, а также Anthropic: OpenAI, Anthropic, Ollama, llama.cpp, vLLM, NeuralDeep или ваш собственный шлюз, с вашими ключами и адресами серверов. Вход через ChatGPT работает через Codex backend. Модели задаются в config.yaml и переключаются для каждой сессии.

Как установить Coddy?

Linux и macOS: curl -fsSL https://coddy.dev/install.sh | bash. Windows: irm https://coddy.dev/install.ps1 | iex. Скрипт скачивает бинарник последнего релиза, добавляет его в PATH и создаёт ~/.coddy/config.yaml на основе примера. В Linux также можно установить пакет .deb или .rpm , публикуемый с каждым релизом (apt-get install ./coddy_X.Y.Z_linux_amd64.deb, dnf install ./coddy_X.Y.Z_linux_amd64.rpm), а в macOS — Homebrew-пакет непосредственно из релиза (brew install --cask https://github.com/coddy-project/coddy-agent/releases/latest/download/coddy.rb). Оба способа регистрируют Coddy в пакетном менеджере и добавляют man-страницу и автодополнение. Docker: docker run -d --name coddy -p 12345:12345 -e OPENAI_API_KEY -v "$PWD/workspace:/workspace" -v "$PWD/coddy_home:/home/user/.coddy" ghcr.io/coddy-project/coddy-agent:latest открывает веб-интерфейс по адресу localhost:12345; на вкладке Docker также есть docker-compose.yaml для копирования. Многоархитектурные образы (amd64, arm64) опубликованы в GitHub Container Registry. coddy update -y обновляет существующую установку.

Можно ли запускать Coddy локально с локальными моделями?

Да. Укажите для модели локальный сервер, совместимый с OpenAI, например Ollama, llama.cpp или vLLM: запросы не покинут вашу сеть. Статический бинарник работает и в контейнерах distroless или минимальных образах с файловой системой только для чтения — по одному агенту на задачу.

В каких редакторах и клиентах работает Coddy?

coddy acp использует Agent Client Protocol через stdio, поэтому Zed, Obsidian, VS Code или ваш скрипт получают сессии, режимы, разрешения, потоковые обновления и навыки как слеш-команды. coddy serve запускает остальные компоненты в одном процессе: REST API, совместимый с OpenAI, встроенный веб-интерфейс, шлюз Telegram, ретранслятор узлов и планировщик cron. Он включает те из них, которые разрешены в config.yaml . Они используют общие сессии, поэтому разговор, начатый в чате, виден в веб-интерфейсе и может быть продолжен там или в чате.

Как запустить Coddy на нескольких компьютерах?

Запустите coddy serve на каждом компьютере и включите ретранслятор узлов на одном из них: он объединит сессии, будет маршрутизировать запросы и подключит узлы, доступные только через исходящее соединение, по обратному туннелю. Консоль, coddy acpи веб-интерфейс также могут работать с отдельным удалённым сервером через --remoteи coddy serve --daemon оставляет сервер работать в фоне через status, stopи restart.

Чем Coddy отличается от других агентов для программирования?

Coddy не привязан к провайдеру и рассчитан на собственный сервер: один бинарник под лицензией MIT без зависимостей от среды выполнения, ваши ключи или локальные модели и общие сессии для терминала, веб-интерфейса, редактора, Telegram и планировщика. Он читает правила и навыки в стиле Cursor, а также AGENTS.md из репозитория, поэтому подходит проектам, уже настроенным для других агентов.
