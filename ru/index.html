Запустите универсального агента
из одного статического бинарника

Coddy - агентный харнес с ReAct-циклом, инструментами для файлов и командной строки, MCP, правилами проекта, навыками, субагентами, хуками, фоновыми задачами и долговременной памятью. Работайте с ним из терминала, браузера, редактора по ACP или Telegram, запускайте как сервис с планировщиком cron, ретранслятором для роя узлов и удалённым управлением откуда угодно. Рассчитан на контейнеры и ваши собственные ключи API.

/go-binary /console-tui /acp-harness /subagents /swarm /distroless-ready /on-prem-llms

Посмотреть скрипт установки ↗

Запустите команду в PowerShell. Она положит бинарник последнего релиза в PATH и создаст ~/.coddy/config.yaml из примера, если его ещё нет. 

docker run -d --name coddy \
  -p 12345:12345 \
  -e OPENAI_API_KEY \
  -v "$PWD/workspace:/workspace" \
  -v "$PWD/coddy_home:/home/user/.coddy" \
  ghcr.io/coddy-project/coddy-agent:latest
services:
  coddy:
    image: ghcr.io/coddy-project/coddy-agent:latest
    command: serve -H 0.0.0.0 -P 12345
    ports:
      - "12345:12345"
    working_dir: /workspace
    environment:
      CODDY_HOME: /home/user/.coddy
      CODDY_CWD: /workspace
      CODDY_CONFIG: /home/user/.coddy/config.yaml
      OPENAI_API_KEY: ${OPENAI_API_KEY-}
    volumes:
      - ./workspace:/workspace
      - ./coddy_home:/home/user/.coddy
    healthcheck:
      test: ["CMD", "/bin/coddy", "--version"]
      interval: 5s
      timeout: 3s
      retries: 20
Руководство по Docker ↗ Compose-файл в репозитории ↗

Открывает веб-интерфейс по адресу localhost:12345. Агент работает в смонтированном каталоге /workspace; сессии, навыки и конфигурация лежат во втором томе. Образ собирается для amd64 и arm64 и публикуется в GitHub Container Registry, скачать его можно без входа в реестр. Вместо latest лучше закрепить конкретный релиз, например ghcr.io/coddy-project/coddy-agent:X.Y.Z.

Сохраните файл как docker-compose.yaml и запустите docker compose up -d. В репозитории лежат Dockerfile, docker-compose.yml для опубликованного образа и docker-compose.dev.yml для сборки из исходников со своими тегами.

Затем впишите ключ провайдера в ~/.coddy/config.yaml и запустите

coddy
терминальная консоль
coddy serve
веб-интерфейс
coddy acp
редактор по ACP
coddy update -y
будущие обновления

Coddy в работе

Тот же агент, запущенный через coddy serve: потоковые вызовы инструментов, карточка разрешения с настоящим diff, история сессий, семь тем и переключатель окружения, который направляет интерфейс на удалённый сервер.

Команда coddy без аргументов в терминале. Выберите модель через Ctrl+L, подтверждайте правки и команды по ходу работы агента, продолжайте сессию через coddy -c и подключайтесь к удалённому серверу через --remote.

Zed запускает coddy acp для рабочего каталога. Режимы, модели и политика разрешений Coddy появляются в панели агента, а навыки становятся слеш-командами. Хватит одной записи в settings.json: 

"agent_servers": {
  "Coddy": { "type": "custom", "command": "coddy", "args": ["acp"] }
}

Что такое Coddy

Coddy начинался как агент для программирования и вырос в универсальный харнес: правила и навыки в стиле Cursor на диске, режимы agent, plan и ask, разрешения инструментов, потоковый вывод и сессии, которые можно продолжить из терминала, IDE, браузера, Telegram или автоматизации. Какой бы интерфейс ни открыл сессию, за ней стоит тот же каталог $CODDY_HOME.

Поставляйте его одним бинарником в образах distroless или scratch либо запускайте парк контейнеров под оркестратором, который задаёт CPU, память и тома. На каждую задачу свой агент с полным контролем над экземпляром, а один ретранслятор роя видит все узлы и связывается с любым из них.

Возможности

Ядро агента

ReAct-цикл

Рассуждения, вызовы инструментов и наблюдения в цикле. Защита от зацикливания ловит повторяющийся вывод и одинаковые вызовы инструментов.

Субагенты

spawn_agent передаёт ограниченную задачу дочернему агенту с собственным контекстом и сессией. Определения пишутся в Markdown и могут только сужать набор инструментов родителя.

Хуки

Ваши команды на каждом этапе жизненного цикла в формате hooks.json из Claude Code. Хук может запретить, разрешить или переписать вызов инструмента до его запуска.

Фоновые задачи

Долгие команды уходят в фон через background: true. Панель фоновых задач сверяет их ход с оценкой самой модели, а вывод агент забирает позже.

Сжатие контекста

/compact и автоматическая суммаризация при достижении порога контекста. Последние ходы остаются дословно, а полный транскрипт хранится на диске.

Долговременная память

Необязательный копайлот памяти вспоминает сведения из прошлых сессий, а в HTTP API у каждой сессии есть свои маршруты памяти.

Где запускать

Консоль

Команда coddy без аргументов в терминале. Потоковый транскрипт, блоки инструментов, окна разрешений, !! для локальной оболочки, которую модель не видит, coddy -c для продолжения сессии, coddy -p для разового вывода.

Веб-интерфейс

Встроенный SPA по адресу / в сборке с тегами http,ui. Чат, сессии, планы, панели фоновых задач и планировщика, карта роя и настройки на лету.

ACP

coddy acp по stdio. Сессии, режимы, разрешения и потоковые обновления для Zed, Obsidian, VS Code или вашего скрипта.

HTTP API

Шлюз, совместимый с OpenAI, в coddy serve. POST /v1/responses, модели, Swagger по адресу /docs/.

Шлюз Telegram

Адаптер бота с отдельными сессиями для каждого пользователя, режимами изоляции групп, ACL администраторов и нативным форматированием сообщений. Расширяется на другие мессенджеры.

Сессии

Каталоги сессий лежат на диске в $CODDY_HOME и открываются из любого интерфейса. Правка сообщения создаёт ветку диалога, а /export выгружает сессию в Markdown, HTML или JSON.

Эксплуатация

coddy serve

Один процесс для всех подсистем, включённых в config.yaml. --daemon уводит его в фон, где им управляют status, stop и restart, а изменённый конфиг подхватывается без перезапуска.

Рой узлов

Ретранслятор видит множество узлов и связывается с ними, собирает их сессии в один список и маршрутизирует запросы между кольцами. Узлы, у которых есть только исходящий доступ, подключаются через обратный туннель.

Удалённое управление

Подключите консоль или coddy acp к работающему серверу через --remote или переключайте веб-интерфейс между локальным и удалённым сервером из поля ввода.

Планировщик

Задачи cron с панелью в интерфейсе и инструментами для агента, поэтому повторяющаяся работа идёт без открытой сессии.

Проверка конфигурации и пробный запуск

coddy -t проверяет config.yaml по встроенной схеме, указывает file:line:col и предлагает исправление. --dry-run ещё до старта опрашивает пути, провайдеров, модели, порты, MCP-серверы и удалённые узлы.

Docker и distroless

Готовые образы лежат в ghcr.io для amd64 и arm64, а можно положить статический бинарник в образ scratch с rootfs только для чтения.

Контекст проекта и контроль

Правила

Сам находит .cursor/rules, .coddy/rules, .agents/rules, .claude/rules, .codex/rules и вложенные AGENTS.md в рабочем каталоге сессии.

Навыки

Слеш-команды из наборов SKILL.md в skills.dirs. Устанавливаются из реестров через npx skills или из раздела Настройки → Навыки.

MCP-серверы

Подключайте MCP-серверы по stdio, streamable HTTP и SSE из конфига, файлов mcp.json или из редактора. Их инструменты попадают в циклы режимов agent и plan.

Три режима

agent работает со всеми инструментами, plan пишет только планы, ask только читает и ищет, включая веб-поиск.

Разрешения и доверие

Перед правкой или командой агент спрашивает разрешение, и его можно выдать сразу на всю программу. MCP-серверы, хуки и файлы субагентов из самого проекта сначала нужно явно одобрить.

Самонастройка

Агент правит собственный YAML поэтапными командами config_set. Изменения применяются только после одобренного вами коммита, который проверяет конфиг и перезагружает его на лету.

Модели, инструменты и оформление

Любой провайдер

OpenAI, Anthropic, Ollama, NeuralDeep, любой API, совместимый с OpenAI, и вход через ChatGPT на бэкенде Codex. Ключи и адреса серверов ваши.

Уровни рассуждения

Выпадающий список в поле ввода задаёт уровень рассуждения для reasoning-моделей, который переводится в параметр OpenAI reasoning_effort или в бюджет thinking у Anthropic.

Мультимодальность

Прикрепляйте изображения и файлы в поле ввода, если модель это поддерживает. Вложения сохраняются в каталог сессии и попадают в контекст агента.

Расход и лимиты

Квота текущей модели видна в нижней строке консоли и в веб-интерфейсе, если провайдер её публикует. Ход, упёршийся в лимит, может дождаться сброса и продолжиться сам.

Команды SSH

ssh_run_command ходит на удалённые хосты по SSH на чистом Go и авторизуется через ваш SSH-агент или ключи из ~/.ssh.

Темы и язык

Семь тем веб-интерфейса и английский или русский язык. Всё переключается в разделе Настройки → Оформление без правки конфига.

Вопросы

Что такое Coddy Agent?

Coddy Agent - универсальный ИИ-агент с открытым исходным кодом, который поставляется одним статическим Go-бинарником под лицензией MIT. Внутри ReAct-цикл с инструментами для файлов и командной строки, MCP-серверы, правила проекта, навыки, субагенты, хуки, фоновые задачи, планировщик cron и долговременная память. Один и тот же агент доступен из терминала, браузера, редактора по ACP или Telegram, на одной машине или в рое из нескольких.

С какими провайдерами и моделями работает Coddy?

Любой API, совместимый с OpenAI, а также Anthropic: OpenAI, Anthropic, Ollama, llama.cpp, vLLM, NeuralDeep или ваш собственный шлюз, всегда с вашими ключами и адресами серверов. Войти через ChatGPT можно с помощью бэкенда Codex. Модели описываются в config.yaml и переключаются отдельно для каждой сессии.

Как установить Coddy?

Linux и macOS: curl -fsSL https://coddy.dev/install.sh | bash. Windows: irm https://coddy.dev/install.ps1 | iex. Скрипт скачивает бинарник последнего релиза, кладёт его в PATH и создаёт ~/.coddy/config.yaml из примера. В Linux вместо этого можно поставить пакет .deb или .rpm, который выходит с каждым релизом (apt-get install ./coddy_X.Y.Z_linux_amd64.deb, dnf install ./coddy_X.Y.Z_linux_amd64.rpm), а в macOS есть Homebrew-пакет прямо из релиза (brew install --cask https://github.com/coddy-project/coddy-agent/releases/latest/download/coddy.rb). Оба способа регистрируют Coddy в пакетном менеджере и ставят man-страницу и автодополнение. Docker: docker run -d --name coddy -p 12345:12345 -e OPENAI_API_KEY -v "$PWD/workspace:/workspace" -v "$PWD/coddy_home:/home/user/.coddy" ghcr.io/coddy-project/coddy-agent:latest открывает веб-интерфейс по адресу localhost:12345, а на вкладке Docker в блоке установки есть ещё docker-compose.yaml для копирования. Мультиархитектурные образы (amd64, arm64) публикуются в GitHub Container Registry, на Docker Hub их нет. coddy update -y обновляет уже установленный Coddy.

Можно ли запускать Coddy на своих серверах с локальными моделями?

Да. Если направить модель на локальный сервер, совместимый с OpenAI, например Ollama, llama.cpp или vLLM, ни один промпт не покинет вашу сеть. Бинарник статический, поэтому работает и в контейнерах distroless или scratch с корневой файловой системой только для чтения, по агенту на задачу.

В каких редакторах и клиентах работает Coddy?

coddy acp работает по Agent Client Protocol через stdio, поэтому Zed, Obsidian, VS Code или ваш скрипт получают сессии, режимы, разрешения, потоковые обновления и навыки в виде слеш-команд. coddy serve запускает всё остальное в одном процессе (REST API, совместимый с OpenAI, со встроенным веб-интерфейсом, шлюз Telegram, ретранслятор роя и планировщик cron) и включает те компоненты, которые разрешены в config.yaml. У них общие сессии, поэтому разговор, начатый в чате, сразу виден в веб-интерфейсе, и продолжить его можно в любом из двух.

Как запустить Coddy на нескольких машинах?

Запустите coddy serve на каждой машине и включите ретранслятор роя на одной из них. Он соберёт сессии всех узлов в одном месте, будет маршрутизировать запросы между кольцами и подтянет через обратный туннель машины, у которых есть только исходящий доступ. Консоль, coddy acp и веб-интерфейс тоже умеют работать с отдельным удалённым сервером через --remote, а coddy serve --daemon держит сервер в фоне под управлением status, stop и restart.

Чем Coddy отличается от других агентов для программирования?

Coddy изначально не привязан к провайдеру и рассчитан на собственный хостинг: один бинарник под лицензией MIT без зависимостей от среды выполнения, ваши ключи или локальные модели и общие сессии для терминала, веб-интерфейса, редактора, Telegram и планировщика. Он читает правила и навыки в стиле Cursor, а также AGENTS.md из репозитория, поэтому подходит проектам, уже настроенным под других агентов.
