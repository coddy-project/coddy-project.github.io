Что такое Coddy — кратко

Coddy называет себя платформой для агентов не случайно. Основа объединяет протоколы — сервер ACP JSON-RPC, менеджер сессий, конфигурацию и MCP — с циклом ReAct поверх сменяемых провайдеров LLM. Агент для программирования — один из профилей с собственными инструкциями и набором инструментов. Измените их, и та же основа станет другим агентом.

Это влияет на развёртывание: один статический Go-бинарник помещается в scratch или distroless без системной оболочки. Инструменты grep и glob используют системный ripgrep, если он есть, иначе переходят на встроенную реализацию Go. Поэтому агент работает даже в контейнере без дополнительных программ.

Все точки входа используют общую $CODDY_HOME: coddy acp для редакторов, обычный coddy для терминальной консоли и coddy serve для REST-шлюза, встроенного веб-интерфейса и мессенджеров в одном процессе. Начатая в терминале сессия открывается в браузере и продолжается в редакторе, потому что её данные хранятся в одном месте на диске. Кроме того, --remote подключает консоль или ACP к удалённому серверу.

Несколько механизмов заслуживают отдельного упоминания: в других системах они встречаются редко. Удаление устаревших результатов заменяет устаревший вывод read и grep заглушками в контексте модели, а keep_result позволяет модели закрепить нужные данные. Встроенный ограничитель циклов останавливает повторяющийся поток и не допускает повторного запуска инструмента с идентичными аргументами. При ограничении частоты запросов обёртка выдаёт типизированную ошибку QuotaResetError, а с agent.wait_for_limit_reset ход ждёт восстановления квоты и повторяет тот же вызов. Самонастройка даёт агенту поэтапные команды для собственного YAML в стиле UCI. Файл меняется только после подтверждённого вами коммита, который проверяет данные, создаёт снимок и применяет настройки без перезапуска.

Как устроен рынок

К середине 2026 года выделились четыре группы. Их прямое сравнение без учёта назначения может вводить в заблуждение.

CLI разработчиков моделей — Claude Code, Codex CLI, Antigravity CLI, Grok Build, Qwen Code, Kimi CLI. Их создают поставщики моделей; эти инструменты задают стандарты (AGENTS.md, MCP, навыки) и обычно связаны с подпиской.

Открытые универсальные платформы — OpenCode, Pi, OMP, DeepSeek Harness, Crush, Reasonix, CodeWhale, Goose, Aider, Cline, OpenHands, Continue и Coddy. Именно здесь особенно заметна конкуренция возможностей.

Шлюзы персональных помощников — OpenClaw, Hermes Agent и множество подобных проектов. Для персонального агента сначала важны каналы связи, очереди, сессии и память; модель подключается к этому ядру.

Коммерческие платформы — Amp, Cursor CLI, Factory Droid, Devin. Они предлагают командные процессы, параллельную работу и интеграцию с трекерами задач.

12 сентября в таблицы добавились два продукта российского рынка из разных групп. Koda — закрытый продукт по подписке от бывшей команды GigaCode: плагин IDE на основе Continue, CLI на основе Gemini CLI, настольное приложение, управляющее CLI через ACP, и удалённый доступ через Telegram. Drift — персональный агент NeuralDeep в составе подписки на платформу: размещённый сервис с ботом Telegram, веб-приложением и API, совместимым с OpenAI. Каждому пользователю выделяется отдельный Docker-контейнер; открытие исходного кода анонсировано на этот год.

На события года повлияли два случая. 18 июня Google отключила Gemini CLI для личных аккаунтов и перевела пользователей на закрытый Antigravity CLI на Go: это нарушило работу некоторых CI-процессов и сократило бесплатный лимит примерно с тысячи до двадцати запросов в день. В марте произошла утечка исходников Claude Code, после чего появилась независимая реализация Claw Code на Python и Rust, быстро набравшая звёзды на GitHub. Вторая история не меняет техническое сравнение, но объясняет скачки популярности в 2026 году.

Преимущества и ограничения Coddy

Сильные стороны

  • Возможности в одном бинарнике Шесть из двадцати проектов поставляются одним статическим файлом без среды выполнения. Только Coddy включает в этот же файл веб-интерфейс, планировщик, долговременную память и шлюз мессенджера, включаемые тегами сборки.
  • Множество интерфейсов с общими сессиями Reasonix тоже предлагает четыре интерфейса, но вместо шлюза мессенджера использует канал QQ. Koda работает в терминале, редакторах, настольном приложении и Telegram, однако её плагин и CLI — разные форки с отдельными сессиями. У персональных шлюзов больше каналов связи, но слабее средства разработки и нет ACP.
  • Самонастройка Ни одна другая платформа из списка не предоставляет типизированные поэтапные правки собственного YAML с проверкой, снимком, применением без перезапуска и откатом.
  • Доверие к файлам из репозитория MCP-серверы, определения субагентов и файлы хуков проходят единый механизм подтверждения, привязанный к рабочему каталогу, файлу и его хешу. После изменения файла Coddy спрашивает снова. Claude Code доверяет по имени, Codex — по каталогу, а у Koda унаследованная от Gemini CLI проверка доверия к каталогу по умолчанию выключена.
  • Совместимость с существующими форматами Правила Cursor и Claude Code, субагенты и hooks.json, в стиле Cursor mcp.json, AGENTS.md и навыки по стандарту agents загружаются без преобразования. Сопоставимую совместимость предлагает только OMP.
  • Удаление результатов с возможностью закрепления Модель может помечать данные, которые нужно оставить в контексте. Среди рассмотренных проектов это есть только у Coddy и Reasonix, причём у Reasonix для другой цели.

Недостатки

  • Нет изоляции на уровне ядра Защиту дают запросы разрешений, режимы и контейнер с файловой системой только для чтения. Codex CLI применяет Landlock, seccomp и Seatbelt прямо в процессе — это существенно при работе с чужим кодом. Koda сохранила необязательную изоляцию Gemini CLI через Docker, Podman или Seatbelt, а Drift выделяет каждому пользователю отдельный контейнер в размещённом сервисе.
  • Нет LSP и DAP OMP использует языковой сервер при каждом изменении и управляет отладчиками; OpenCode поддерживает LSP примерно для двадцати языков. Coddy работает с файлами как с текстом, поэтому переименование по всему проекту выполняется через поиск.
  • Обычный формат правок Формат hashline в OMP привязывает патч к хешу содержимого: по сравнению с заменой строк он сокращает число выходных токенов примерно на 61% и повышает надёжность слабых моделей. Coddy использует обычные edit и apply_patch.
  • Нет снимков рабочего каталога Reasonix делает снимок на каждом ходе, CodeWhale сохраняет рабочий каталог, Grok Build изолирует запуски в рабочих деревьях, а Koda сохраняет теневой Git-репозиторий Gemini CLI с помощью /restore. Coddy откатывает конфигурацию и создаёт ветви сессий, но не восстанавливает файлы.
  • Нет режима параллельного распределения задач Субагенты работают, но нет встроенного процесса вида «распределить задачу между N рабочими деревьями и объединить результаты», как в Grok Build и OMP.
  • Размер экосистемы Аудитория на три порядка меньше, чем у OpenCode. Именно пользователи первыми находят ошибки, пишут навыки и обнаруживают крайние случаи. Поддержка навыков и правил других инструментов частично помогает, но сопоставимого каталога плагинов пока нет.

Что выбрать

Выбирайте Coddy, если агент должен работать в контейнере без оболочки, одна сессия должна открываться в терминале, редакторе, браузере и Telegram, повторяющимся задачам нужен встроенный планировщик, а в репозиториях уже есть правила Cursor или Claude Code.

Выбирайте другое решение, если работаете с большим проектом и нужны быстрые правки с учётом символов: здесь OMP или OpenCode предлагают больше. Для запуска незнакомого кода сильнее изоляция Codex CLI. Для персонального помощника в мессенджерах подходят OpenClaw или Hermes.

Если важны оплата в рублях и доступ без VPN, рассмотрите Koda и Drift. Koda предлагает IDE и терминал по подписке со своими моделями. Drift — размещённый персональный агент в Telegram с изоляцией, планировщиком и памятью; он не работает с вашим репозиторием.

Попробуйте Coddy. Одна команда установит бинарник, создаст ~/.coddy/config.yaml и добавит coddy в PATH. Используйте свой ключ или локальную модель.
