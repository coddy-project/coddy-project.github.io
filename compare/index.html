What Coddy is, in one section

Coddy calls itself a harness and means it. The core is protocol plumbing - an ACP JSON-RPC server, a session manager, configuration, MCP wiring - plus a ReAct loop over swappable LLM providers. The coding agent is a product profile on top, assembled from prompts and a default toolset. Change the prompt and the toolset and the same core becomes a different agent.

The practical consequence is delivery. One static Go binary drops into scratch or distroless with no system shell. The grep and glob tools use system ripgrep when it exists and fall back to built-in Go implementations when it does not, so the agent still works in a container that holds nothing but the agent.

Every entry point shares one $CODDY_HOME: coddy acp for editors, bare coddy for the terminal console, and coddy serve for the REST gateway, the embedded web UI and the messengers, in one process. A session started in the terminal opens in a browser and continues in an editor, because the session bundle lives in one place on disk. On top of that, --remote points the console or ACP at a running server elsewhere.

A few mechanisms are worth naming because they rarely show up elsewhere. Result eviction collapses stale read and grep output into placeholders in the projection sent to the model, while keep_result lets the model pin what it still needs. The loop guard cuts a stream that degenerates into repetition and stops re-running a tool called with byte-identical arguments. On a rate limit the resilient wrapper raises a typed QuotaResetError, and with agent.wait_for_limit_reset the turn sleeps until the quota returns and then replays the very same call. Self-configuration gives the agent staged, uci-style commands over its own YAML, where nothing touches the file until a commit you approve, which validates, snapshots and hot-reloads.

How the field splits

By mid-2026 the genre had separated into four camps, and comparing them on one set of axes only confuses things.

Lab CLIs - Claude Code, Codex CLI, Antigravity CLI, Grok Build, Qwen Code, Kimi CLI. Built by the model vendors, they set the conventions (AGENTS.md, MCP, skills) and live next to a subscription.

General-purpose open harnesses - OpenCode, Pi, OMP, DeepSeek Harness, Crush, Reasonix, CodeWhale, Goose, Aider, Cline, OpenHands, Continue and Coddy. This is where the feature race actually happens.

Personal assistant gateways - OpenClaw, Hermes Agent and a swarm of clones. Their premise is that a personal agent hits the gateway problem before it hits the model problem, so the first thing they build is a process owning channels, queues, sessions and memory, with the model attached to the side.

Commercial platforms - Amp, Cursor CLI, Factory Droid, Devin. They sell team workflows, parallelism and tracker integrations.

Two rows from the Russian market joined the tables on 12 September, one on each side of that split. Koda is a closed subscription product from the former GigaCode team: an IDE plugin forked from Continue, a CLI forked from Gemini CLI that its own desktop app drives over ACP, and a Telegram remote for both. Drift is the personal agent NeuralDeep bundles with its hub subscription: a hosted service with a Telegram bot, a web app and an OpenAI-compatible API, every user in a Docker container of their own, and an open-source release announced for this year.

Two events shaped the year. Google switched Gemini CLI off for individual accounts on 18 June and moved everyone to the closed, Go-based Antigravity CLI, breaking CI pipelines on the way and cutting the free tier from a thousand requests a day to roughly twenty. And in March the Claude Code sources leaked, which produced Claw Code, a clean-room rewrite in Python and Rust that set a GitHub record for star velocity. The second story does not affect the technical picture, but it explains why 2026 star counts jump around so much.

Where Coddy wins, where it lags

Strengths

  • Density per binary Six of the twenty ship as one static file with no runtime. Only Coddy also carries the web UI, the scheduler, long-term memory and a messenger gateway inside that same file, switched on with build tags.
  • Breadth of surfaces over shared state Reasonix matches the four-surface layout, but trades the messenger gateway for a QQ channel. Koda reaches a terminal, editors, a desktop app and Telegram too, but its plugin and its CLI are two different forks with separate sessions. Gateway assistants have more channels and weaker coding, and no ACP.
  • Self-configuration No other harness in this set exposes typed, staged edits to its own YAML with validation, a snapshot, hot reload and a rollback.
  • Trust for files that arrive with a checkout MCP servers, subagent definitions and hook files all pass one receipt mechanism bound to the workspace, the file and its digest. Rewrite the declaration and Coddy asks again. Claude Code gates by name, Codex by folder, and Koda inherits Gemini CLI's folder trust with the feature switched off.
  • Compatibility instead of a private format Cursor rules, Claude Code rules, subagents and hooks.json, Cursor-style mcp.json, AGENTS.md and agents-standard skills all load as they are. Only OMP does something comparable.
  • Result eviction with explicit pins A model that marks what to keep in context, found here only in Coddy and Reasonix, and in Reasonix it serves a different goal.

Gaps

  • No kernel-level sandbox Protection comes from the permission gate, the modes, and a container with a read-only rootfs. Codex CLI enforces Landlock, seccomp and Seatbelt in the process itself, which matters more than any dialog when the code is not yours. Koda keeps Gemini CLI's optional Docker, Podman or Seatbelt sandbox, and Drift runs every user in a container of their own on its hosted side.
  • No LSP, no DAP OMP wires a language server into every edit and drives real debuggers; OpenCode ships LSP for twenty-odd languages. Coddy treats files as text, so a project-wide rename goes through grep.
  • Plain edit format OMP's hashline anchors a patch to a content hash, cutting output tokens by about 61% against string replacement and lifting patch success sharply on weaker models. Coddy uses ordinary edit and apply_patch.
  • No workspace checkpoints Reasonix snapshots every turn, CodeWhale snapshots the workspace, Grok Build isolates runs in worktrees, Koda keeps Gemini CLI's shadow git repository behind /restore. Coddy rolls back configuration and branches sessions, but not files.
  • No fan-out mode Subagents run, but there is no built-in "split this across N worktrees and merge the results" workflow of the kind Grok Build and OMP ship.
  • Ecosystem size Three orders of magnitude fewer people than OpenCode, and those are the people who file bugs, write skills and hit the edge cases first. Reading other tools' skills and rules softens this; a plugin registry of comparable size is not coming.

When to pick which

Choose Coddy when the agent has to live inside a container with no shell, when one session must open from a terminal, an editor, a browser and Telegram, when recurring work needs a scheduler with no external cron, and when your repositories already carry Cursor or Claude Code rules you would rather not rewrite.

Choose something else when the day is spent on a large codebase with a strong model and you want fast, symbol-aware edits - OMP or OpenCode give more there. Running unfamiliar code from an unfamiliar repository is safer under Codex CLI and its sandbox. For a personal assistant that lives in messengers, OpenClaw or Hermes are built for exactly that.

A stack paid in roubles and reachable without a VPN is a separate question. Koda covers the IDE and the terminal on a subscription with its own models; Drift is a personal agent in Telegram with a sandbox, a scheduler and a memory, hosted for you and never pointed at your repository.

Try the row you just read about. One command installs the binary, writes ~/.coddy/config.yaml and puts coddy on your PATH. Bring your own key, or point it at a local model.
